# Editor validation (scripted)

`validate.js` drives the **built** Electron app over the DevTools protocol (`--remote-debugging-port=9350`) using **real mouse and keyboard events** against the production editor (the `#debug` URL hash installs `window.__wts`, which exposes in-renderer objects only). It is **automation, not hand-testing by a person**. It covers Phase 4 (Layers panel, inspector, selection, rename, lock/visibility, reorder, properties, add/duplicate/delete, multi-selection, group/ungroup, 50+ layers, accessibility scan, save/reopen) plus Phase 3B regression checks (drag, resize, rotate, off-canvas, snapping, zoom, exact-size render, Node isolation).

Run: `npm run build`; launch `WALKONE_DEV_SAVE_PATH=<tmp>/V.boothproject WALKONE_DEV_OPEN_PATH=<same> npx electron out/main/index.js --remote-debugging-port=9350 --user-data-dir=<tmp>/ud`; then `node research/editor-validation/validate.js`. Native dialogs are answered by the dev-only env overrides (ignored by packaged builds). `results.json` is the recorded Phase 4 macOS run (97/97). `validate-4b.js` (Phase 4B) launches the built app itself, kills it with SIGKILL and relaunches it on the same user-data dir to validate close/quit prompts, autosave and crash recovery (40/40 in `results-phase4b.json`). Screenshots go to a git-ignored `shots/` folder.
