# Editor validation (scripted)

`validate.js` drives the **built** Electron app over the DevTools protocol (`--remote-debugging-port=9350`) using **real mouse and keyboard events** against the production editor (the `#debug` URL hash installs `window.__wts`, which exposes in-renderer objects only). It is **automation, not hand-testing by a person**. It covers Phase 4 (Layers panel, inspector, selection, rename, lock/visibility, reorder, properties, add/duplicate/delete, multi-selection, group/ungroup, 50+ layers, accessibility scan, save/reopen) plus Phase 3B regression checks (drag, resize, rotate, off-canvas, snapping, zoom, exact-size render, Node isolation).

Run: `npm run build`; launch `WALKONE_DEV_UNSAVED_CHOICES=discard WALKONE_DEV_SAVE_PATH=<tmp>/V.boothproject WALKONE_DEV_OPEN_PATH=<same> npx electron out/main/index.js --remote-debugging-port=9350 --user-data-dir=<tmp>/ud`; then `node research/editor-validation/validate.js`. Native dialogs are answered by the dev-only env overrides (ignored by packaged builds). `results.json` is the recorded Phase 4 macOS run (97/97). `validate-4b.js` (Phase 4B) launches the built app itself, kills it with SIGKILL and relaunches it on the same user-data dir to validate close/quit prompts, autosave and crash recovery (40/40 in `results-phase4b.json`). Screenshots go to a git-ignored `shots/` folder.

**Phase 4C:** `validate-4c.js` (97 checks, `results-phase4c.json`) launches the built app itself for each scenario (welcome, editor, recovery, autosave issue, four window sizes via the dev-only `WALKONE_DEV_WINDOW_SIZE`) using the shared `harness.js`. `validate.js` was adapted to the redesigned UI (menus for Close/Open/Save As/stacking/Add layer; run with the `WALKONE_DEV_*` variables exported for both the app and the script) and still passes 97/97; `validate-4b.js` still passes 40/40. All are automation, not human testing, and screenshots (`shots/`, git-ignored) are for human review.

**Phase 4D:** `validate-4d.js` (6 checks, `results-phase4d.json`) sweeps the renderer viewport from 1100 to 1920 px in 40 px steps with DevTools device-metrics emulation (not real frame dragging) and records computed-style facts for the polish items.

**Phase 5A:** `validate-5a.js` (53 checks, `results-phase5a.json`) launches the built app, generates fixture images (PNG via zlib; JPEG/WebP/large JPEG via Pillow), and covers import (all formats), drawer, add/move/resize/rotate, roles, save/reopen, alpha pixel sampling, background fit modes, dedup, error model, remove used/unused, replace, drag and drop at three zoom/pan states (synthetic DataTransfer events through the real handlers), SIGKILL recovery with assets, and the security boundary. Dev-only dialog override added: `WALKONE_DEV_IMPORT_PATHS` (files separated by `|`, dialogs by `;`, `CANCEL`). Automation, not human testing.

**Phase 5B:** `validate-5b.js` (39 checks, `results-phase5b.json`) covers the strip New Project dialog, Design / Print Preview, sheet pixel checks, nudging at four zooms, exact selection X/Y, align/distribute, group X, save/reopen. The debug hook gained `__wts.renderSheetToDataUrl`. Automation, not human testing.

**Phase 5C:** `validate-5c.js` (59 checks, `results-phase5c.json`): overflow/clipped view, exact-render clipping, zoom and pointer-centred zoom, Shift-constrained drag (3 zooms, jitter, mid-gesture release, snap, multi-select), Space pan, preview photos, shuffle, fit, crop (Reposition mode), frame/radius, real hover tooltips, save/reopen and SIGKILL recovery. The harness now launches Electron with `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-features=CalculateNativeWinOcclusion` and `Page.bringToFront`: without them macOS can mark the window occluded (another app in front, display asleep) and mouse/wheel input silently stalls, which caused earlier flaky runs. The debug hook gained `stageSnapshot()` and a `preview` argument on the render hooks. Automation, not human testing.

**Phase 5D:** `validate-5d.js` (40 checks, `results-phase5d.json`): font picker, missing-font handling, inventory, replace-all, Fit height, Event Palette linking/global change/detach/custom colours, Print Preview, save/reopen, SIGKILL recovery, security. The debug hook gained `textFont(id)` (the font stack a canvas text node draws with). Automation, not human testing.

**Phase 6A:** `validate-6a.js` (48 checks at 6A; 37 since the layer package left the dialog — its ZIP/band checks are in git history at eca330e; `results-phase6a.json`) builds a 2×6 strip, exports Print sheet / Design / Proof / Layer package through the real Export dialog into a temp folder (dev-only overrides `WALKONE_DEV_EXPORT_DIR`, ';'-separated per picker, `CANCEL`; `WALKONE_DEV_NO_REVEAL=1`), and measures the files with `inspect-export.py` (python3 + Pillow, run with `-P`): sizes, DPI, copy identity, proof vs production, package alpha/pixels, band re-stacking = design.png, manifest. Also conflicts, cancel, Escape, ⌘E, preflight warning/blocking, single-up, reveal, project untouched, security. Automation, not human testing.

**After 6A:** `validate-resize-snap.js` (9 checks, `results-resize-snap.json`): real corner-handle drags of a photo slot snap to another slot's width/height with same-size marks shown, far drags and Snap off do not snap, and a white-framed slot at a fractional position exports a proof with no grey hairline (measured with Pillow). Automation, not human testing.

**Phase 6B:** `validate-6b.js` (26 checks, `results-phase6b.json`) exports the dslrBooth templates (native 2×6 strip and 4×6 sheet) plus the production PNGs through the real dialog and opens the ZIPs with `inspect-dslr.py` (python3 + Pillow): archive order/compression, BOM/CRLF, attribute order compared with the local fixtures (attribute names only), the images stacked by ZIndex vs Template Studio's own PNG (pixel-exact), simulated booth photos under frames and rounded corners, and preflight blocking. `validate-6a.js` now unticks the dslrBooth templates (37 checks). Automation, not human testing, and not dslrBooth itself.
