# Architecture Plan (Proposed)

**Status (2026-11-17): implemented through Phase 6D.** Sections 1–4 and 7–14 began as the pre-build plan; the "implemented" sections (5–6, 5a–5i) describe the code as it is. Where they differ, the implemented sections and [DECISIONS.md](DECISIONS.md) win. Canvas library: **Konva with react-konva** (ADR-029). Not used despite the early plan: Sharp, JSZip, fast-xml-parser, SQLite (archives use yauzl/yazl, ADR-025; XML is read by a small in-house strict reader, ADR-048).

## 1. Principles
Desktop-first, local-first; strict separation of UI, editor state, rendering, storage, and export adapters; vendor-neutral domain; testable pure modules; deterministic rendering; offline-capable; no speculative abstraction.

## 2. Preferred stack (Proposed)
Electron, React, TypeScript (strict), Vite, Zustand, Sharp, JSZip, fast-xml-parser, SQLite where appropriate. Canvas: Konva + react-konva (ADR-029). Each is validated in its relevant phase and recorded in [DECISIONS.md](DECISIONS.md).

## 3. Process model
- **Main process:** app lifecycle, windows, filesystem, dialogs, ZIP/XML/image processing orchestration, SQLite, secrets, integrations. Heavy work in worker threads/utility processes to keep UI responsive.
- **Preload:** minimal, typed `contextBridge` API. No Node in renderer.
- **Renderer:** React UI, editor state, canvas. Never touches the filesystem directly.
- **Security model:** `contextIsolation` on, `nodeIntegration` off, sandboxed renderer, strict CSP, IPC channels allowlisted and validated (schema-checked payloads), no arbitrary path access — paths come from user-chosen dialogs or app-managed directories. Safe ZIP extraction. Untrusted SVG sanitized.

## 4. Layers and boundaries
```
UI (React) ──► editor state (Zustand + commands/history)
                    │
                    ├─► domain (pure TS: model, geometry, palette, validation rules)
                    ├─► canvas/render abstraction (interface; Fabric/Konva behind it)
                    └─► services via IPC: projects, assets, importers, exporters, integrations
```
- **Domain:** no Electron/React/DOM imports; unit-testable.
- **Editor state:** commands over the domain model for undo/redo; selection and view state separate from document state.
- **Canvas abstraction:** the editor talks to an engine contract (props in: domain project, images, selection, view transform, snapping; events out: normalized `GeometryChange[]`, selection, guides; handle: export/benchmark hooks) so the library stays swappable; the library never owns the source of truth (the domain model does). The Phase 3A spike (`src/renderer/src/spikes/canvas/`) prototyped this contract with both Fabric and Konva.
- **Canvas rules from the spike (ADR-029):** design coordinates are in design pixels; the view (zoom/pan) is only a Stage transform; Konva nodes use a box-center origin (`offsetX/Y` = half size) so rotation matches the domain; after a transform, scale is folded into width/height and reset; group children are absolute in the domain and baked back from runtime-group matrices; photo placeholders are single custom-drawn `Shape`s (`sceneFunc` + `hitFunc`); text uses `Text` with an HTML overlay for editing; exports render in a neutral view at the requested pixel size with an explicit `pixelRatio`; snapping is a pure function with a screen-pixel tolerance converted to design units.
- **Rendering/export:** a deterministic renderer producing pixels from the domain model for preview and export, ideally sharing logic so preview == export (approach — e.g., Sharp-based compositing vs canvas-based — **Needs Validation**, may require parity tests).

**Implemented (Phase 2):** `src/domain/` exists as a pure module with sub-folders `print/ layers/ palette/ assets/ color/ compatibility/ project/ validation/`, exposed through `src/domain/index.ts` and the `@domain` alias; zod is the runtime validator; Vitest runs `src/**/*.test.ts`. See ADR-018–024.

## 5. State management (implemented in Phase 3B)
A Zustand **vanilla** store (`src/editor/store.ts`, ADR-030) holds the open project once, plus selection (`selectedIds` array, multi-select-ready), view state (`fit | manual`), viewport size, interaction mode, text-edit target, snapping/guide settings, photo display mode, snapshot history (ADR-031), and the saved-project reference for dirty state. Pure mutations (`src/editor/mutations.ts`): `addLayer`, `updateLayer`, `removeLayer`, `duplicateLayer`, `moveLayerBy`, `resizeLayer`, `rotateLayer`, `setLayerGeometry`, `commitGeometry` (one interaction, many layers), `setVisibility`, `setLocked`, `setLayerZIndex`, `reorderLayer`; each returns a new validated project with `updatedAt` refreshed. Store actions add lock checks, selection handling, history and working-copy write-through (latest-wins, no timers, no package rebuild). Rules: duplicate preserves `photoNumber`; deleting a group deletes its descendants; deleting the last child removes the empty group; locks/visibility inherit from ancestors; zIndex is dense per sibling set with array order as tie-break.

## 5a. Canvas architecture (implemented in Phase 3B)
```
src/canvas/        pure + Konva-type-only modules (no React, no Electron)
  geometry/        centre-box conversion, matrices, matrix -> domain geometry
  viewport/        fit/zoom/pan math, ViewState, snap tolerance (CSS pixels; DPR never enters)
  snapping/        computeSnap (canvas edges/centre, other layers)
  transforms/      normalizeNodeTransform/Text/FromMatrix, min size, transformer options per layer type
  rendering/       nodeSpec (how every layer type is drawn: one spec for editor AND offscreen render), draw
                   (photo placeholder, fitted image), color, plan (pure render plan), renderProject (Konva offscreen)
  adapters/        konvaCommit (Konva node -> domain geometry, scale reset), konvaSnap (drag snapping)
  assets/          ImageCache (decoded images, injected loader)
src/editor/        pure store, mutations, history, ports
src/renderer/src/editor/   React: EditorCanvas (react-konva), TextEditOverlay, keyboard hook, EditorScreen, asset loader
```
Konva stage layers: `workspace` (backdrop + shadow, inert), `printable` (design background + layer nodes), `editor-overlay` (print-area dimming mask, snap guides, Transformer). Only the printable layer exists in `renderProjectToCanvas`, so editor chrome can never leak into output. Z-order is `sortedSiblings` (zIndex, then array order), never insertion order. All nodes use a box-centre origin; after a transform the scale is folded into width/height/fontSize and reset to 1. Photo placeholders are one custom `Shape`; groups are runtime `Konva.Group`s baked back to absolute child geometry. Zoom is a Stage transform only. Text editing is an HTML textarea overlay (Enter commits, Shift+Enter newline, Escape cancels, blur commits). Image bytes arrive through the `readAsset` bridge (ADR-032).

Canvas, Layers panel and Properties inspector are three views/controllers over ONE store (`src/editor/store.ts`); none keeps its own copy of layers. Pure, tested modules: `layerTree.ts` (panel rows, front-first order, direct vs inherited lock/visibility, collapse and filter), `selection.ts` (toggle/range), `newLayers.ts` (add-layer defaults, `nextPhotoNumber`), `naming.ts`, `numberInput.ts` (parse/format/opacity percent/hex), `describe.ts`, plus mutations `renameLayer`, `moveLayerRelative`, `reorderLayers`, `groupLayers`, `ungroupLayer` and `topmostIds`/`transformTargets` helpers. Editor-only UI state in the store (never in the project, history or dirty state): `collapsedGroups`, `layerFilter`, `selectedIds`, `anchorId`. React: `LayersPanel` (memoized rows, pointer-based reorder, tree keyboard model), `PropertiesInspector` with `fields.tsx` (draft-then-commit controls; `useDraft().take()` prevents an Enter+blur double commit), `EditorScreen` (toolbar, project rail, status bar), `platform.ts` (Command on macOS, Control elsewhere). The canvas uses one shared Transformer for multi-selection; `EditorCanvas` commits a whole interaction (all selected nodes) as one `commitGeometry`. Decisions: ADR-033.

`renderer/src/styles/` (tokens, base, ui, shell, panels CSS) and `renderer/src/ui/` (reusable components) are the presentation layer; `renderer/src/editor/` holds the screens: `EditorScreen` (layout), `TopBar`, `ToolRail`/`ToolDrawer`, `StatusBar`, `Welcome`, `NewProjectDialog`, `RecoveryDialog`, `LayersPanel`, `PropertiesInspector`, `fields.tsx`. The main process adds a minimal native menu (`main/appMenu.ts`) and the minimum window size. No domain, store-behaviour or persistence code changed.

## 6. Persistence (implemented in Phase 2B)
**Code layout:** `src/projects/` is Node-only and Electron-free (testable with Vitest): `packageReader` / `packageWriter` (yauzl / yazl), `atomicFile`, `session`, `recents`, `service` (`ProjectService`), `handlers` (pure IPC handlers with injected dialogs), `errors`. `src/main/projectIpc.ts` wires Electron dialogs and `ipcMain`; `src/preload` exposes `window.api.project.*`; `src/shared/ipc.ts` + `persistence.ts` hold the typed contract. The renderer never touches the filesystem and never receives session paths.
**Two stores:** the **portable package** (`.boothproject`, used for Save/Save As/transfer) and the **working session** (`<userData>/sessions/<id>/` — `project.json`, `assets/`, `session.json`) used while a project is open. Autosave (debounced in the editor store, Phase 4B) calls `updateWorkingCopy`, which rewrites only the small working `project.json` and metadata, never the archive.
**Open:** validate extension → scan central directory (limits, path/link/encryption/duplicate checks) → read and validate `project.json` (schema + integrity + package asset-path rules) → verify referenced assets exist → create session → extract assets (size/sha256 checked) → return project, clean. Any failure removes the half-built session.
**Save / Save As:** serialize and validate → verify assets in session → write `<dest>.tmp-xxxx` via yazl (fixed order, fixed timestamps/modes → deterministic bytes) → reopen and verify the temp package → fsync → atomic replace (below) → mark session clean and update recents. Save As changes the file association only after success.
**Atomic replace (ADR-028):** `rename(tmp, dest)` replaces atomically on macOS/Linux and normally on Windows. If the OS refuses to rename over the existing file (EPERM/EEXIST/EBUSY/EACCES), the old file is moved to a backup name, the new file renamed in, and the backup deleted; if the second rename fails the backup is restored. The existing file is never truncated; temp files are removed on failure. Limits: no cross-volume atomicity (temp is created beside the destination), and directory fsync is best-effort.
**Dirty state:** `dirty` means "differs from the last successful portable save/open", computed by comparing the SHA-256 of the serialized project with `portableHash`. Autosave never clears it; only Save/Save As (or opening a package) does. It lives in the session metadata and `ProjectService`, not React state.
**Close/quit and recovery (Phase 4B, ADR-034):** `src/main/closeCoordinator.ts` (pure decision table) and `documentLifecycle.ts` (window `close`, `before-quit`, native prompt, renderer state/save requests over `document:request`/`document:response`, `document:requestClose`). `src/editor/autosave.ts` is the debounce/maxWait/backoff scheduler used by the store. `src/projects/recovery.ts` scans sessions at startup by owner token (not PID), removes clean/untouched sessions, quarantines corrupt/old ones, and lists the rest; `ProjectService.recover/discardRecovery/closeAll` implement the actions. macOS: closing the last window does not quit; Cmd+Q uses `before-quit`; a single window and a single instance are assumed.
**Recents (ADR-026):** `<userData>/recent-projects.json` (`{version:1, items:[{path, projectId?, name, lastOpenedAt}]}`), max 10, atomic writes, corrupted file set aside as `.corrupt`; missing files flagged `exists:false`. `openRecent` only accepts paths already in this list.
**SQLite (ADR-012)** remains reserved for future library/index features, not project files or recents.
**Errors:** every failure is a `PersistenceError` with a code (`file-not-found`, `invalid-project`, `unsupported-version`, `corrupted-package`, `missing-asset`, `unsafe-path`, `permission-denied`, `write-failed`, `replace-failed`, `session-not-found`, `not-allowed`, `invalid-request`, `unexpected`) and a user-safe message; internal detail is logged in main only. IPC returns `{status:'ok'|'cancelled'|'error'}` — cancellation is not an error.
**Dev-only dialog override:** non-packaged builds honor `WALKONE_DEV_OPEN_PATH` / `WALKONE_DEV_SAVE_PATH` so scripted validation can answer native dialogs; packaged builds ignore them.

## 7. Image, ZIP, XML
Sharp for raster ops/compositing (native module → packaging per-platform concern, **Risk**); JSZip for ZIP; fast-xml-parser for XML parse/build. All wrapped in thin modules so they are replaceable and testable.

## 8. Importers/exporters (adapters)
**As built:** `src/export/dslrbooth/` (exporter, 6B) and `src/import/dslrbooth/` (importer, 6D; ZIP reading in `src/projects/dslrImport.ts`) depend on `domain`, never the reverse. Original plan: `importers/dslrbooth` and `exporters/dslrbooth` depend on `domain`, never the reverse. Native format and PNG/layer exporters follow the same interface shape. Adapters return result objects with warnings.

## 9. Assets and integrations
Asset service manages library/project assets. `integrations/<provider>` behind capability interfaces; core runs without them ([ASSET_AND_INTEGRATION_STRATEGY.md](ASSET_AND_INTEGRATION_STRATEGY.md)).

## 10. Validation / preflight
Pure rule functions over the domain model plus context (asset metadata, fonts); each rule returns typed issues (error/warning, layer ref, fix hint). Adapter-specific rules live with the adapter.

## 11. Testing boundaries
Domain/validation/adapters = pure unit + fixture tests; rendering = visual tests; main-process services = integration tests; UI = component + manual QA ([TESTING_STRATEGY.md](TESTING_STRATEGY.md)).

## 5d. Project assets (implemented in Phase 5A, ADR-036)
`src/projects/imageInspect.ts` (byte-based format detection, header metadata, SVG policy) and `ProjectService.importAssetFiles/importAssetBytes` (validate → SHA-256 de-dup → atomic copy into `<session>/assets/<id>.<ext>`) are Node-only and Electron-free. Assets belong to the logical design, so a future two-up compositor copies the whole design rather than assets.

## 15. Future: shared Template Studio core for WalkOne Booth (ADR-049, planning only)
Template Studio stays a standalone app and will also run at full capability inside WalkOne Booth from **one shared core** (domain, rendering, editor, typography, palettes, assets, photo slots, composition, preflight, safe area, native format, dslrBooth adapter). A likely future split, **conceptual only and not to be done now**: `apps/template-studio`, `apps/walkone-booth`, `packages/template-domain` (today `src/domain`), `template-editor` (`src/editor`, `src/canvas`, renderer editor UI), `template-renderer` (`src/canvas/rendering`), `template-export` (`src/export`, `src/import`), `output-profiles` (future), `shared-ui` (renderer `ui/`, `styles/`), `shared-contracts` (`src/shared`).
**Rules until then:** keep the domain free of Electron/React/DOM; keep editor state behind injected ports (`EditorPorts`); keep main-process services Electron-free where possible and reachable only through typed IPC contracts; keep vendor adapters out of the domain; never put company profile, output/printer profiles, credentials or event data into `TemplateProject`. WalkOne Booth itself: a **modular monolith** (Events, Templates, Capture, Camera, Rendering, Printing, Sharing, Media, Settings as internal modules), Windows-first, offline-tolerant (capture and printing never wait for the network; sharing jobs queue and retry), OS-backed credential storage. Details and open questions: [PRODUCT_ECOSYSTEM.md](PRODUCT_ECOSYSTEM.md).
