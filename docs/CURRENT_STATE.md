## Phase 6D — DSLR Booth importer (done)
**File › Import dslrBooth template…** and **Import from dslrBooth…** on the start screen. Main shows the ZIP picker and analyses the file; a dialog shows dslrBooth's own preview, the facts (size, DPI, photos per session, pictures), for two-strip 4×6 sheets the choice **one 2×6 strip printed two per sheet** (recommended when the copies match) or **the sheet exactly as it is**, and "What to know" notes for the chosen layout. Import asks about unsaved changes, then opens a new, Modified, never-saved project (Save asks where). Photo slots become photo slots, pictures become image layers with project assets, locks/visibility/rotation/opacity are kept, `print_2_per_page` becomes two-up output; anything not understood (unknown elements/attributes, shadows, dropped strip copies, missing pictures) is kept in `sourceCompatibility.dslrbooth` and listed — never silently dropped; the machine name is not kept. A ZIP that is not a template shows a clear error with "Choose another…". Re-exporting an imported template gives the same photo boxes.
**Verified:** 876 unit tests (XML reader incl. DTD rejection and limits; mapping; two-strip detection; ZIP safety incl. path escape, junk files, folder-wrapped ZIPs, too many entries; choose → commit handlers; save/reopen; compatibility pruning; the five private fixtures when present: all import with no warnings and every photo slot exports back to its original box) and **validate-import.js 17/17** in the built app (synthetic two-strip ZIP + the five local fixtures: as-is renders are as close to each template's own preview as a direct rebuild of the XML, mean difference 1.5–4.3/255; the kept strip of a strip import is pixel-identical to the original outside photo boxes except at the 4 px strip edge where the original's copy overlapped).
**Not verified / known limits:** no real dslrBooth import of a re-exported imported template yet (6C); imported text and decorations are pictures (dslrBooth stored them flattened), so they cannot be retyped; Windows untested; templates from other dslrBooth versions untested (unknown structure is preserved and reported); a strip import clips each strip to its half, so artwork that crossed the middle of the original sheet loses the crossing part (reported).

## Phase 6B (done)
The Export dialog lists **For dslrBooth** first: **dslrBooth template · 2×6 strip** (ticked; `<Project>.zip`, one strip, `print_2_per_page="True"` so dslrBooth prints two per 4×6) and, for strips, **dslrBooth template · 4×6 sheet** (`<Project> 4x6.zip`, both copies pre-placed like hand-built templates; fallback until 6C). A single-up project offers one template. **Mapping:** photo slots → native `<Photo>` (number, integer box, whole-degree rotation; inward-rounded when a frame/mask covers the edge); everything else → full-canvas PNG `<Image>`s by stacking order (opaque base behind the first photo, a transparent image above each run of photos; overlapping photos split the run so the stack is exact); **text always rasterized** (booth needs no fonts); **frames and rounded corners** drawn into the image above the photo (dslrBooth borders grow outward and it has no corner radius); `preview.png` with numbered placeholders. **Package** copies the fixtures: BOM + CRLF `template.xml`, observed attribute order/defaults, descending ZIndex, flat deflated ZIP in case-insensitive order, ZIP name = template Name, no machine name in `OriginalDevice`, stable 25-character `Id`. **dslrBooth checks** (only when a dslrBooth template is ticked): no photo slots / PhotoNumber > 12 block; fit ≠ Cover, photo opacity, unusual DPI warn; rotation, flattening, two-up noted. The main process re-reads and verifies the package before writing. Code: `src/export/dslrbooth/` (profile, templateXml, container, plan, preflight, outputs); renderer `exportActions.ts`; main `exportService.ts` (`format: 'dslrbooth'`); `renderOutputToCanvas` gained `background: 'transparent'`. **No schema change, no `.boothproject` change, no new dependency.** **Verified:** gate green, **805 unit tests**; `validate-6b.js` **26/26** on the built macOS app (ZIPs re-opened with Python/Pillow: order, compression, BOM/CRLF, attribute order equal to the local fixtures, images stacked = Template Studio's own design/print PNG pixel-exact, simulated booth photos under frames, rounded corners masked, both sheet copies; preflight blocking); regressions 6A 37/37 (script now unticks the dslrBooth templates), resize-snap 9/9, 4C 97, 4D 6, 5A 53, 5D 40, 5B 39 and 4B 40 (both failed once in a parallel run, passed on rerun). **Test-environment issue (not a code defect):** `validate-5c.js` check 26 (crash recovery after reopen) failed 58/59 because a 5C test app from an interrupted background run (17:19) was still running and held debug port 9510, so later 5C runs partly drove that stale app (confirmed: port 9510 answers from a temp `wts-5c-…` profile). It also "failed" at the 6A commit for the same reason. Closed: the hung run and its app were stopped, and `validate-5c.js` passes 59/59 (5D 40/40 in the same session). **Not verified:** dslrBooth itself (Phase 6C: import, native strip with `print_2_per_page`, `Dimensions="0"` on a strip canvas, rotation pivot, same-`Id` re-import, printing/cut); Windows. **Known limits:** the dialog now scrolls to show Checks; artwork is not separately editable inside dslrBooth (edit in Template Studio and re-export); photo opacity and Fit/Stretch slots are not representable.

## Phase 6A (done)
Export dialog (top-bar Export, File → Export…, ⌘E): **Print PNG** (the print sheet; a 2×6 strip gives the derived 4×6 with both copies), **Design PNG** (one copy; offered when the sheet holds several), **Proof PNG** (print with the current sample photos and crops; "Not for printing", `-proof` name, not watermarked, unticked by default), **Layer package** ZIP (semantic bands by stack position around the photo slots: background / frames / overlay / text, plus design.png, proof.png, manifest.json, readme.txt; re-stacking reproduces design.png unless the manifest notes otherwise). Production pixels = every printable layer + native photo frames, photo areas empty, no samples/labels, clipped to the design/cells. **Preflight** (vendor-neutral): errors block (invalid composition, missing/unreadable image, broken palette colour, invalid photo number), warnings allow (no slots, slot past edge, layer outside, missing font, < 150 DPI image), notes (photo-number gaps, clipped artwork, unknown font, 150–300 DPI, hidden layers); **repeated photo numbers are never reported**; DSLR limits are left to 6B. **Files:** main-owned folder picker → opaque destination id; verification (safe names, PNG signature + exact pixel size, safe flat entries); conflict step (Replace / Keep both → "Name (2)" / Cancel); atomic per-file writes; PNG density in `pHYs`; deterministic ZIP; Show in Finder/Explorer for written files only. Export never modifies the project. ADR-014 accepted (Konva is the production renderer), ADR-041; ADR-015 updated (6A text is rasterized). Research note [../research/DSLRBOOTH_748_RUNTIME_FINDINGS.md](../research/DSLRBOOTH_748_RUNTIME_FINDINGS.md) records the owner-reported dslrBooth 7.48 interoperability rules for 6B. **No schema change, no `.boothproject` change, no new dependency.** Also fixed: Escape now closes a dialog even when focus fell out of it, and editor shortcuts are ignored while a modal is open (previously Delete/⌘Z could act behind a dialog when focus was on the page body). **Verified:** typecheck/lint/format/build; **752 unit tests** (673 + 79); `validate-6a.js` **48/48** on the built macOS app (real exported files measured with Pillow; automation); regression suites 4:97, 4B:40, 4C:97 (first run 93/97 — four recovery-dialog checks in the SIGKILL/autosave-timing scenario; 97/97 on rerun), 4D:6, 5A:53, 5B:39, 5C:59, 5D:40. **Not verified:** a human visual review of the dialog; opening the files in Photoshop/Preview by a person; Windows (Konva/Chromium anti-aliasing and font rasterization may differ from macOS; Windows file-name and Explorer reveal behaviour); a real "Show in Finder" (suppressed by a dev override in automation); very large canvases; DSLR Booth itself. **Known limits:** no cancel while rendering (seconds at most for 4×6 @ 600 DPI); proof and package always use the current preview samples (built-in or session-picked) — there is no separate proof-photo picker; the layer package is design-level (one strip), not sheet-level; layer package bands are not editable text (text is rasterized); literal per-layer PNGs are deferred; the last export folder is remembered only for the current app run; preflight items do not yet select the affected layer.

## After 6A (owner testing follow-up, done)
From the owner's first manual export test. **Resize snapping (Canva-style):** dragging a resize handle now snaps the moving edge(s) to the canvas edges/centre and to other objects' edges/centres, **and to the same width or height as another object** (e.g. size one photo slot, add more, and drag each to match). Pink same-size marks (dimension bars) show on every object that now shares that size; guides as for moving. Corner handles that keep the ratio (photos, images, text) snap the closest axis and derive the other, keeping the opposite corner fixed. Not applied to rotated boxes, the rotate handle, or Alt/Option centred scaling; follows the status-bar Snap toggle. Pure logic in `src/canvas/snapping/resizeSnap.ts` (unit-tested), Konva glue in `konvaSnap.ts` (`snapTransformerBox`, Transformer `boundBoxFunc`). **Photo-frame hairline fixed:** at fractional positions a faint grey line could show along the outer edge of a framed slot in the editor preview and the proof PNG (the picture bled through the frame's anti-aliased outer pixel); the picture/tint is now clipped ≤ 1 px inside the frame's outer edge. Print/design PNGs were never affected (no photos). **Verified:** gate green, **760 unit tests**; `validate-resize-snap.js` **9/9** on the built macOS app (real handle drags; proof pixels measured with Pillow; automation); regressions 4:97, 5A:53, 5C:59, 6A:48. **Not verified:** by a person; Windows. No schema/`.boothproject` change, no dependency. **Layer package withdrawn from the Export dialog** (owner decision, ADR-041 §8: the booth composites the photos itself, clients should never need Canva/Photoshop); the dialog offers Print / Design / Proof; the classification/ZIP code stays for 6B. `validate-6a.js` now 37/37 (package checks retired).
