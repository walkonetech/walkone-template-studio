## Phase 7B · B5.5 — Custom Format / Custom Size wizard (2026-11-22, ADR-059 Accepted, ADR-060; CLOSED — Mac + Windows validated at `86f69fd`)
For magnet and keychain inserts, wallet/mini prints, squares, takeaway cards, badges and other operator sizes. **Format** (what is designed) ≠ **Output Composition** (how it is arranged) ≠ **Output Profile** (how it is produced): the three stay separate; Output Profiles are unchanged (ADR-053).
- **Domain review (before coding):** `single` already expressed exact size; `grid` expressed copies with ONE gap, centred, ≤ 8 × 8. Missing: margins, separate row/column gaps, top-left placement. **Smallest coherent extension:** optional `grid.rowGap`, `grid.margins {top,right,bottom,left}`, `grid.align 'center'|'start'` and optional `canvas.safeMarginMm` (the format's generic design safe margin). Absent = pre-B5.5 behaviour; writers omit defaults (`normalizeGridLayout`); no field became required.
- **Schema version (owner architectural review, ADR-060):** the first draft kept every file at v1, but older builds reject unknown fields, so a B5.1 build could not parse every "v1" file B5.5 wrote — two incompatible shapes under one number. Settled rule: **a file's `schemaVersion` is the oldest version whose readers can parse it.** `CURRENT_SCHEMA_VERSION` = 2; writers stamp the lowest version that represents the content (`fileSchemaVersion`): a project that uses `canvas.safeMarginMm` or grid `rowGap`/`margins`/`align` is written as **v2** (an older build answers "this app supports up to 1. Update the app"); one that uses none is still written as **v1**, byte-identical to before, so standard 2×6 / 4×6 / 6×4 projects stay readable by older builds. Loading migrates 1 → 2 by re-labelling only (no defaults are added: absence already means the v1 behaviour); in memory a project is always v2; opening never rewrites the file. A file marked v1 that uses a v2 field is refused as invalid; v3+ is refused with "Update the app". Stored v1 samples written by the `cb2f75d` build: `tests/fixtures/projects/schema-v1/` (synthetic).
- **Format model** (`src/domain/print/format.ts`): inches canonical (unrounded) + integer DPI + entered unit; mm = in × 25.4, px = round(in × DPI) (the only rounding; display in 3 / mm 2 / px whole decimals; unit switches never touch the stored value). Limits: > 0, ≤ 100 in, 10–30 000 px a side, ≤ 64 MP per canvas (renderer memory), DPI 1–4800, 1–8 across/down, gaps ≤ 10 in, margins ≤ 50 in, safe margin < half the short side. **Built-in formats** (2×6 strip, 4×6, 6×4 × 300/600) are definitions over the presets; New project (built-in) and the wizard both go through `createProjectFromFormat` → `createProject` (one path; built-ins byte-identical to before).

Wizard: **Size** (in / mm / px, 300 / 600 / custom DPI, live conversion, orientation swap; px keeps its pixels when the DPI changes) → **Printing** (Exact size · Repeat on a sheet · Custom sheet layout; numbered diagram; a layout that does not fit is explained and blocks Next/Create; never scaled; "Show cut guides in Print Preview") → **Safe margin** (None · Recommended 3 mm · Custom; generic guidance, not printer evidence) → **Review** (design, pixels, output, gaps/margins, safe margin, "No printer profile assigned", project name, Save to My formats) → **Create design** opens the normal editor.
